\section{Simplified Contrastive Learning}\label{sec:contrastive_learning}

Learning high-quality and faithful representations of data is a fundamental problem in deep learning, known as \textit{self-supervised learning}. There have been many approaches proposed for this task, many of which do not evidently use the techniques and principles outlined in this manuscript. One such approach is called \textit{contrastive learning}, so named because the learning objective is (roughly speaking) about ensuring that features of ``similar'' data are similar, and features of ``dis-similar'' data are far apart. Contrastive learning solutions are often highly-engineered, empirically designed approaches. In this section, we will describe one such approach named DINO \citep{caron2021emerging}, and use the principles described in the previous chapters to drastically simplify their design decisions while improving the learned representations.

\subsection{Data}\label{sub:contrastive_learning_data}

The data that we will use to explore and simplify the DINOv2 methodology is all 2-dimensional image data. For \textit{training}, we will use the ImageNet-1K and ImageNet-21K datasets. Each sample in the dataset is an RGB image, of varying resolution, and a label indicating the object or scene that the image contains (i.e., the \textit{class} of the image). The ImageNet-1K dataset contains 1.28M training images and 50K validation images partitioned into 1K classes. The ImageNet-21K dataset contains 14.2M training images and 21.8K classes, but the classes are not disjoint (i.e., some classes are subsets of others). Since we are doing self-supervised learning, the labels will not be used during training, only during evaluation. For \textit{evaluation}, we will use a litany of datasets. Of these, the most common is CIFAR-10. CIFAR-10 is a dataset of 60K RGB 32 \(\times\) 32 natural images partitioned into 10 classes, with a pre-established training set of 50K samples and a validation set of 10K samples. The purpose of using CIFAR-10 will be to ensure that models which train on one distribution of images (ImageNet) can generalize to another distribution of images (CIFAR-10). We also refer to other similar datasets, such as CIFAR-100 (disjoint from CIFAR-10), Oxford Flowers, and Oxford Pets.

During training, we scale all images to 224 \(\times\) 224 resolution, so as to ensure that all inputs are the same shape. As is necessary with transformer-like sequence-to-sequence architectures, we \textit{tokenize} the image by chopping it up into several \textit{patches}, which are spatially contiguous sub-segments of the data, as follows.

    \caption{An example of tokenizing an image into patches. \DP{NOTE: this image is from somewhere on the internet, and we should make our own before publishing anything.}}
    \label{fig:patchify}

Each patch, say of size \(P_{H} \times P_{W}\) pixels, is a vector in \(\R^{C \times P_{H} \times P_{W}}\). This vector corresponds to a token. The token vectors are flattened and stacked horizontally into the input data matrix \(\vX \in \R^{D \times N}\). 

For example, suppose that the above image in \Cref{fig:patchify} is a \(72 \times 72\) RGB image (so there are \(3\) channels). It is tokenized into \(9\) patches. Each would be of size \(24 \times 24\), and be represented by a vector of size \(3 \times 24 \times 24 = 1728\). So the input matrix \(\vX\) representing this data would live in the space \(\R^{1728 \times 9}\), wherein we have \(D = 1728\) and \(N = 9\). For all applications we take \(P_{H} = P_{W}\) and \(C = 3\), and for nearly all applications we take \(P_{H} = P_{W} = 16\) so \(D = 256\).

\subsection{Task and Objective Function} \label{sub:contrastive_learning_objective}

Our task is to learn a good representation of the data. Contrastive learning, by and large, does this by defining what properties of the input image we wish the features to reflect, construct images which share these properties but vary others, and set up a loss which promotes that the features of images with shared properties are close and images with different properties are different. The naturally optimal solution to this learning problem is that the learned features preserve the desired properties of the input. However, there are many practical and empirical complications which arise in the course of training contrastive models.

In the case of DINO, the authors propose to use a methodology which produces a single feature vector for the whole image, and desires the feature vector to contain ``global'' (i.e., image-level) information. Accordingly the loss will promote that images with similar global information have similar features and images with different global information have different features.

This seems intuitive, but as previously mentioned, there are several empirical considerations, even while setting up the loss. First and foremost, how should we promote similarities and differences? The answer of DINO \citep{caron2021emerging} is\footnote{In the author's view, inexplicably...} to convert the output features into ``logits'' corresponding to some probability distribution and take their cross-entropy. More specifically, let \(\Delta_{m} := \{\vx \in \R^{m} \colon x_{i} \geq 0\ \forall i, \sum_{i}x_{i} = 1\}\) be the space of probability vectors in \(\R^{m}\) and define the function \(d_{\CE} \colon \R^{m} \times \R^{m} \to \R\) by
 \begin{equation}\label{eq:cross_entropy_difference}
    d_{\CE}(\vp, \vq) := \frac{1}{2}[\CE(\vp, \vq) + \CE(\vq, \vp)], \quad \forall \vp, \vq \in \Delta_{m}
 \end{equation}
 where \(\CE \colon \Delta_{m} \times \Delta_{m} \to \R\) is defined as 
 \begin{equation}\label{eq:expts_def_ce}
    \CE(\vp, \vq) := -\sum_{i = 1}^{m}p_{i}\log q_{i}, \quad \forall \vp = (p_{1}, \dots, p_{m}), \vq = (q_{1}, \dots, q_{m}) \in \Delta_{m}.
 \end{equation}
 Before we continue our discussion, let us build some intuition about this distance function. We have, in particular,
 \begin{align}
    \CE(\vp, \vq)
    &= -\sum_{i = 1}^{m}p_{i}\log q_{i} = \sum_{i = 1}^{m}p_{i}\log(p_{i}/q_{i}) - \sum_{i = 1}^{m}p_{i}\log p_{i} = \KL(\vp, \vq) + H(\vp)
 \end{align}
 where \(\KL \colon \Delta_{m} \times \Delta_{m} \to \R\) is the KL divergence, defined as 
 \begin{equation}
    \KL(\vp, \vq) := \sum_{i = 1}^{m}p_{i}\log(p_{i}/q_{i}),
 \end{equation}
 and \(H \colon \Delta_{m} \to \R\) is the entropy of a random variable. Thus we have 
 \begin{align}
    d_{\CE}(\vp, \vq)
    &= \frac{\CE(\vp, \vq) + \CE(\vq, \vp)}{2} \\
    &= \underbrace{\frac{\KL(\vp, \vq) + \KL(\vq, \vp)}{2}}_{d_{\mathrm{JS}}} + \frac{1}{2}(H(\vp) + H(\vq))
 \end{align}
 where \(d_{\mathrm{JS}}\) is the \textit{Jensen-Shannon} divergence, minimized if and only if \(\vp = \vq\). So minimizing \(d_{\CE}\) does two things: it makes \(\vp = \vq\), and it makes \(\vp\) and \(\vq\) have minimal entropy (i.e., vectors with \(1\) in one component and \(0\) elsewhere --- these are called \textit{one-hot vectors}). Overall, the goal of this objective is not \textit{just} to match \(\vp\) and \(\vq\) but also to shape them in a certain way to make them low-entropy. Keep this in mind when we discuss the formulation.

The next question is, how should we obtain samples with similar global information? The answer of DINO (as well as nearly all contrastive learning) is \textit{data augmentation} --- from each sample, make several correlated samples which share the desired properties. In the DINO case, we use different crops or \textit{views} of the input image. Recall that we model an image as a function \(\R^{D \times N}\). A view is a function \(v \colon \R^{D \times N} \to \R^{D \times N_{v}}\), where \(N_{v}\) is the number of tokens in the view. In this case, the view picks out a subset of tokens such that the underlying patches form a rectangular crop of the image. There are two types of views we want to use: \textit{global views} (i.e., large crops) and \textit{local views} (i.e., small crops), as in \Cref{fig:local_global_views}. In order to process local and global views in a unified way, DINO uses a transformer neural network \(f_{\theta}\), which can process input sequences of any length, i.e., with shape \(\R^{D \times T}\) for every \(T \geq 1\) (formally this space can be denoted as \(\R^{D \times *} := \bigcup_{T = 1}^{\infty}\R^{D \times T}\)). The exact implementation will be discussed shortly in \Cref{sub:contrastive_learning_architecture}, but for now it suffices that we can think of a transformer as a map \(f_{\theta} \colon \R^{D \times T} \to \Sphere^{d-1}\) where \(\Sphere^{d-1} := \{\vx \in \R^{d} \colon \norm{\vx}_{2} = 1\}\) is the \(\ell^{2}\)-sphere in \(\R^{d}\). In this case, the network is used to compute \(f_{\theta}(v(\vX))\) for each (local or global) view \(v\).

DINO desires that the features \(\vZ_{v}(\theta) := f_{\theta}(v(\vX))\) of all views \(v(\vX)\) of an input image \(\vX\) are consistent with each other. DINO does this by minimizing the difference between the features of each global view \(v_{g}\), say \(\vz_{g}(\theta) := f_{\theta}(v_{g}(\vX))\), and each other view \(v_{c}\), say \(\vz_{c}(\theta) := f_{\theta}(v_{c}(\vX))\). Here, \(v_{c}\) can either be a local view or a global view. 

As previously discussed, DINO wants to convert the features \(\vz_{v}(\theta)\) into probability vectors. To do this, they handle the features of the chosen global view separately from the features of the other view, supplying an affine transformation to each one and then applying a ``temperature-weighted softmax''. Define the matrix \(\vW \in \R^{m \times d}\), denoted the ``DINO head'', and the vector \(\vmu \in \R^{m}\), where \(m \gg d\). Also define the temperature parameter \(\tau > 0\). Then DINO computes the probability vectors
\begin{align}
    \vp_{g}(\theta, \vW, \vmu)
    &= \softmax([\vW\vz_{g}(\theta) - \vmu]/\tau), \\
    \vp_{c}(\theta, \vW)
    &= \softmax(\vW\vz_{c}(\theta)/\tau),
\end{align}
where \(\softmax \colon \R^{m} \to \Delta_{m}\) is defined as 
\begin{equation}
    \softmax\rp{\mat{x_{1} \\ \vdots \\ x_{m}}} := \frac{1}{\sum_{i = 1}^{m}e^{x_{i}}}\mat{e^{x_{1}} \\ \vdots \\ e^{x_{m}}}.
\end{equation}
Then DINO solves the problem \(\min_{\theta, \vW, \vmu}L_{\dino}(\theta, \vW, \vmu)\) where 
 \begin{equation}\label{eq:dino_loss}
     L_{\dino}(\theta, \vW, \vmu) := \Ex[d_{\CE}(\vp_{c}(\theta, \vW), \vp_{g}(\theta, \vW, \vmu))], \nonumber
\end{equation}
where the expectation is over data \(\vX\), global views \(v_{g}\), and other views \(v_{c}\).

While it is easy to reason about \eqref{eq:dino_loss}, it is impossible in practice to implement optimization algorithms such as gradient descent with a loss given by \(L_{\dino}\). This is because the expectations in the loss are impossible to evaluate, much less take the gradient of. In this extremely frequent case, we approximate the expectation via finite samples. That is, \textit{at each timestep} \(t\), we:
\begin{itemize}
    \item Subsample \(B\) data points from our dataset \(\{\vX_{1}^{t}, \dots, \vX_{B}^{t}\} \subseteq \R^{D \times N}\).
    \item For each data point \(\vX_{b}^{t}\), sample \(M_{\glo}\) global views \(v_{b, g}^{t, i}\) and \(M_{\loc}\) local views \(v_{b, \ell}^{t, i}\). 
    \item For each \textit{local} view \(v_{b, \ell}^{t, i}\) compute the following quantities:
    \begin{equation}
        \vz_{b, \ell}^{t, i}(\theta) := f_{\theta}(v_{b, \ell}^{t, i}(\vX_{b}^{t})), \qquad \vp_{b, \ell}^{t, i}(\theta, \vW) := \softmax(\vW \vz_{b, \ell}^{t, i}(\theta)/\tau)
    \end{equation}
    and for each \textit{global} view \(v_{b, g}^{t, i}\) compute the following quantities (by an abuse of notation):
    \begin{align}
        &\vz_{b, g}^{t, i}(\theta) := f_{\theta}(v_{b, g}^{t, i}(\vX_{b}^{t})), \qquad \vp_{b, g}^{t, i}(\theta, \vW) := \softmax(\vW \vz_{b, g}^{t, i}(\theta)/\tau), \\
        &\vp_{b, g}^{t, i}(\theta, \vW, \vmu) := \softmax([\vW\vz_{b, g}^{t, i}(\theta) - \vmu]/\tau).
    \end{align}
    \item Perform the optimization update using the \textit{surrogate, approximate loss} \(\hat{L}_{\mathrm{DINO}}^{t}\), defined as follows: 
        \begin{align}\label{eq:dino_loss_empirical}
            \hat{L}_{\dino}^{t}(\theta, \vW, \vmu) :=
            &\frac{1}{BM_{\glo}(M_{\glo} + M_{\loc} - 1)}\sum_{b = 1}^{B}\sum_{i = 1}^{M_{\glo}}\Bigg[\sum_{j = 1}^{M_{\loc}}d_{\CE}(\vp_{b, g}^{t, i}(\theta, \vW, \vmu), \vp_{b, \ell}^{t, j}(\theta, \vW)) \\
            &\qquad  \qquad \qquad \qquad \qquad \qquad \qquad + \sum_{\substack{j = 1 \\ j \neq i}}^{M_{\glo}}d_{\CE}(\vp_{b, g}^{t, i}(\theta, \vW, \vmu), \vp_{b, g}^{t, j}(\theta, \vW))\Bigg]\nonumber
        \end{align}
\end{itemize}
In the general case this transforms our intractable optimization problem, as in optimizing the loss in \eqref{eq:dino_loss}, into a tractable stochastic optimization problem which is run to train essentially every deep learning model in the world. This conversion is extremely natural once you have seen some examples, and we will hopefully give these examples throughout the chapter. 

In this specific case, however, if you try to implement \eqref{eq:dino_loss_empirical} and optimize it on a real network, it is very likely that you run into a problem: after running a few iterations of the learning algorithm, the feature mapping \(f_{\theta}\) will output only a single vector, \textit{no matter what the input is}! This certainly optimizes the above loss since it minimizes the distance between features of different views of the same image. But we obviously do not want to learn this solution. 

Actually avoiding collapse is a very common consideration in contrastive learning. So how to do it in this case? The solution of DINO, again, is empirically designed, and carefully tunes the optimization of the centering parameter \(\vmu\) (which is updated using all samples in the batch) and the temperature parameter  \(\tau\) schedule (i.e., how it varies over the optimization trajectory) in order to ensure non-collapse, given a certain special set of hyperparameters that work well. However, outside of this special configuration, it is very difficult to train models to converge, and the training is highly unstable. We do not highlight the technical details here, but bring up the overall problem so as to showcase our very simple solution.

Now let us discuss simplifications to the formulation. First, instead of using the logits of some affine transformation of the representations, we directly compare the representations themselves. Using our hypothesis from \Cref{ch:representation} that good representations should have Euclidean (subspace) geometry, a much more natural measure of difference is the \textit{squared \(\ell^{2}\) distance} \(d_{\ell^{2}} \colon \R^{d} \times \R^{d} \to \R\), defined as 
\begin{equation}\label{eq:cosine_similarity}
    d_{\ell^{2}}(\vx, \vy) := \frac{1}{2}\norm{\vx - \vy}_{2}^{2}, \qquad  \forall \vx, \vy \in \R^{d}.
\end{equation}
This distance-based score is even more efficient to compute than the cross-entropy score. Thus, \(d_{\ell^{2}}\) takes the place of \(d_{\CE}\) in our simplification. 

Before, collapse was avoided by using tricks to update \(\vmu\) and \(\tau\). In our simplification, if we directly compare the representations instead of converting them to probabilities, we do not have either of these parameters and so must consider a different way to avoid collapse. To do this, we return to the fundamentals. The basic idea of avoiding collapse is that in order to make sure that all samples do not return the same exact same features, we need different samples to have different features. In other words, we would like the \textit{covariance} of the features to be \textit{large} in some sense. But from \Cref{ch:compression,ch:representation}, we already have a quantity which measures the size of the covariance matrix. Namely, we use the straightforward (population-level) \textit{Gaussian coding rate} \(R\) to ensure that the features of global views of different images, which have different global information, are well-separated and not collapsed (hence expanded). The overall modified loss \(L_{\simdino}\) becomes:
\begin{equation}\label{eq:simdino_loss}
    L_{\simdino}(\theta) := \Ex[d_{\ell^{2}}(\vz_{c}(\theta), \vz_{g}(\theta)] - \frac{\gamma}{2}\logdet\rp{\vI + \frac{d}{\eps^{2}}\Cov(\vz_{g}(\theta))},
\end{equation}
where \(\eps > 0\) is fixed and the appropriate expectations are, as before, taken over data \(\vX\), global view \(v_{g}\), and other (local or global) view \(v_{c}\). At time \(t\), we can optimize the following computationally tractable loss:
\begin{align}\label{eq:simdino_loss_empirical}
    \hat{L}_{\simdino}^{t}(\theta) :=
    & \frac{1}{BM_{\glo}(M_{\glo}+M_{\loc}-1)}\sum_{b = 1}^{B}\sum_{i = 1}^{M_{\glo}}\Bigg[\sum_{j = 1}^{M_{\loc}}d_{\ell^{2}}(\vz_{b, g}^{t, i}(\theta), \vz_{b, \ell}^{t, j}(\theta)) \\
    &\qquad \qquad \qquad \qquad \qquad \qquad \qquad + \sum_{j = 1}^{M_{\glo}}d_{\ell^{2}}(\vz_{b, g}^{t, i}(\theta), \vz_{b, g}^{t, j}(\theta))\Bigg] \\
    & + \frac{\gamma}{M_{\glo}}\sum_{i = 1}^{M_{\glo}}R([\vz_{1, g}^{t, i}(\theta), \dots, \vz_{B, g}^{t, i}(\theta)]) \label{eq:simdino_loss_empirical_covariance}
\end{align}
where \(R\) used in \Cref{eq:simdino_loss_empirical_covariance} is the Gaussian coding rate on finite samples defined in \Cref{ch:representation}. Notably, \eqref{eq:simdino_loss_empirical_covariance} is merely a way to approximate the covariance regularization term in \eqref{eq:simdino_loss} while maintaining computational efficiency.

The loss in \eqref{eq:simdino_loss_empirical} is the loss used for the simplified DINO. As we will see, it works equally well or better than the original DINO.

\subsection{Architecture: Vision Transformer}\label{sub:contrastive_learning_architecture}

For the architecture, we use a standard vision transformer. Here is how such an architecture works, formally, in the context of image data. Let \(\vX \in \R^{D \times N}\) be the matrix of patches corresponding to such an image. 
\begin{enumerate}
    \item First, the data \(\vX\) is \textit{preprocessed}, by a map \(f^{\pre} \colon \R^{D \times N} \to \R^{d \times n}\) where \(n = N + 1\), as follows:
    \begin{equation}
        f^{\pre}(\vX) = [\vz_{\cls}^{1}, \vW^{\pre}\vX] + \vE^{\pos}.
    \end{equation}
    Here we have three trainable parameters \(\vW^{\pre}\), \(\vz_{\cls}^{1}\), and \(\vE^{\pos}\) whose purpose is as follows:
    \begin{itemize}
        \item \(\vW^{\pre} \in \R^{d \times D}\) is a matrix which projects each patch vector to a token feature.
        \item \(\vz_{\cls}^{1} \in \R^{d}\) is a so-called \textit{class token} or \textit{register token}. The class token heuristically holds global information of the whole data and is used for downstream tasks. In the framework of compressive deep networks from \Cref{ch:representation}, we expect that the class token is projected onto the same subspaces as the salient or semantically relevant tokens during the progression of the forward pass.
        \item \(\vE^{\pos} \in \R^{d \times n}\) is a so-called \textit{positional encoding} which distinguishes different tokens from each other. That is, token features should have positional information, so that the overall map \(f^{\pre}\) is not invariant to permutations of the patches, and \(\vE^{\pos}\) inserts this positional information. 
        \begin{itemize}
            \item We previously discussed the encoding of certain sub-matrices of \(\vX\), where all rows are kept but only a few columns are removed during data augmentation. In these cases we use the sub-matrix of \(\vE^{\pos}\) corresponding to the original positions of the columns, instead of the full \(\vE^{\pos}\) matrix (which after all is the wrong shape).
        \end{itemize}
    \end{itemize}
    \item Then, the data \(\vZ^{1} = f^{\pre}(\vX)\) is passed through \(L\) \textit{layers} \(f^{\ell}\). The iteration \(f^{\ell}\) has the following implementation:
    \begin{align}
        \vZ^{\ell + 1/2}
        &= \vZ^{\ell} + \MHSA^{\ell}(\LN_{1}^{\ell}(\vZ^{\ell})) \\ 
        \vZ^{\ell + 1}
        &= \vZ^{\ell + 1/2} + \MLP^{\ell}(\LN_{2}^{\ell}(\vZ^{\ell + 1/2}))
    \end{align}
    and \(f^{\ell}(\vZ^{\ell}) := \vZ^{\ell + 1}\). Here we have used some operators, such as \(\MHSA, \MLP, \LN\) that are defined as follows:
    \begin{itemize}
        \item The \(\MHSA\) operator is multi-head-self-attention, the predecessor of the multi-head subspace self-attention (cf \Cref{ch:representation}). The formulation is as follows:
        \begin{align}
            \MHSA(\vZ) \label{eq:mhsa}
            &:= \vU_{\out}\mat{([\vU_{\val}^{1}]^{\top}\vZ)\vA^{1}(\vZ) \\ \vdots \\ ([\vU_{\val}^{K}]^{\top}\vZ)\vA^{K}(\vZ)}, \\
            \text{where} \qquad \vA^{k}(\vZ) \label{eq:attention_map}
            &:= \softmax\rp{\frac{([\vU_{\key}^{k}]^{\top}\vZ)^{\top}([\vU_{\query}^{k}]^{\top}\vZ)}{\sqrt{d}}}
        \end{align}
        where \(p\) is a positive integer, \(\vU_{\query}^{i}, \vU_{\key}^{i}, \vU_{\val}^{i} \in \R^{d \times p}\) and \(\vU_{\out} \in \R^{d \times Kp}\) are trainable parameters, and the \(\softmax\) is defined column-wise as 
        \begin{align}
            \softmax(\vM) 
            &:= \mat{\softmax(\vm_{1}) & \cdots & \softmax(\vm_{p})}, \\ 
            \forall \vM 
            &= \mat{\vm_{1}, \dots, \vm_{p}} \in \R^{n \times p}.
        \end{align}
        In practice, the dimensions are usually picked is usually picked such that \(Kp = d\). The terms \(\vA^{k}(\vZ)\) and \((\vU_{\val}^{k}\vZ)\vA^{k}(\vZ)\) are also known as the \textit{\(k\th\) attention map} and \textit{\(k\th\) attention head output} respectively.
        \item The \(\MLP\) is a two-layer perceptron, a regular nonlinearity used in deep networks, and has the form 
        \begin{equation}
            \MLP(\vZ) := \vW_{\down}\ReLU(\vW_{\up}\vZ + \vb_{\up}\vone_{n}^{\top}) + \vb_{\down}\vone_{n}^{\top}
        \end{equation}
        where \(\vW_{\up} \in \R^{m \times d}, \vW_{\down} \in \R^{d \times m}, \vb_{\up} \in \R^{m}, \vb_{\down} \in \R^{d}\) are trainable parameters, and \(\ReLU\) is the element-wise ReLU nonlinearity, i.e., \(\ReLU(\vM)_{ij} = \max\{M_{ij}, 0\}\). 
        \item The layer-norm \(\LN\) is a standard normalization, which applies column-wise to each token independently:
        \begin{equation}
            \LN(\vZ) = \LN(\mat{\vz_{1}, \dots, \vz_{n}}) = \mat{\LN(\vz_{1}), \dots, \LN(\vz_{n})}
        \end{equation}
        and has the form 
        \begin{equation}
            \LN(\vz) = \frac{\vz - \vmu(\vz)\vone_{d}}{\norm{\vz - \vmu(\vz)\vone_{d}}_{2}} \odot \valpha + \vbeta \qquad \text{where} \qquad \vmu(\vz) = \frac{1}{d}\vone_{d}^{\top}\vz
        \end{equation}
        where \(\odot\) denotes element-wise multiplication, and \(\valpha, \vbeta \in \R^{d}\). The layer-norm operator serves as a sort of normalization on each token, where the scale of each token afterwards is learnable and shared amongst all tokens.
    \end{itemize}
    \item After the data has made it through preprocessing and \(L\) layers, we obtain the features \(\vZ = \mat{\vz_{1}, \dots, \vz_{n}}\). In the DINO context, we want to use the class token representation (which, again, has global information), so we extract \(\vz_{1}\) from this matrix (mathematically it's equivalent to return the result of \(\vZ \ve_{1}\)).  We call this post-processing step \(f^{\post}\).
\end{enumerate}
Thus the neural network is of the form 
\begin{equation}
    f = f^{\post} \circ f^{L} \circ \cdots \circ f^{1} \circ f^{\pre} \colon \R^{D \times N} \to \R^{d}.
\end{equation}
The transformer is one of the most popular neural network architectures in history, powering applications in almost all fields of deep learning. 

For the DINO application in particular, they choose to make one small architectural addition which we carry forward into SimDINO, producing a network \(\tilde{f}\): they use a small two-layer MLP to post-process the output of \(f\), followed by a parameter-free normalization, i.e., return the function
\begin{equation}
    \tilde{f} \colon \vX \mapsto \frac{\MLP^{\post}(f(\vX))}{\norm{\MLP^{\post}(f(\vX))}_{2}}
\end{equation}
instead of \(\tilde{f}\) itself. In particular, this means that the output of the encoder network in DINO (and SimDINO) is normalized to be on the \(\ell^{2}\)-sphere \(\Sphere^{d-1}\).

\subsection{Optimization Strategy}\label{sub:contrastive_learning_optimization}

We have a loss function and an architecture, so we now discuss the optimization strategy. The optimization strategy for DINO uses \textit{two sets of weights for the same architecture}: \textit{student} weights \(\theta_{\student}\) and \textit{teacher} weights \(\theta_{\teacher}\). These correspond to two different neural networks, called the teacher network and student network, with the same architecture. The teacher network encodes all global views, while the student network encodes all ``other'' views. The goal of the loss is to distill teacher outputs into the student model. Namely, we train on the loss \(L_{\dino{}-\student\teacher}\):
\begin{equation}\label{eq:dino_loss_teacherstudent}
    L_{\dino{}-\student\teacher}(\theta_{\student}, \theta_{\teacher}, \vW, \vmu) := \Ex[d_{\CE}(\vp_{c}(\theta_{\student}, \vW), \vp_{g}(\theta_{\teacher}, \vW, \vmu))],
\end{equation}
with an analogous stochastic sample-wise loss (cf \eqref{eq:dino_loss} to \eqref{eq:dino_loss_empirical}), say denoted \(\hat{L}_{\dino-\student\teacher}^{(k)}\) on iteration \(k\). The optimization strategy is also unconventional: only the student parameters \(\theta_{s}\) as well as \(\vW\) are optimized, while \(\theta_{t}\) as well as \(\vmu\) is directly constructed via an exponential moving average. For SGD this looks like:
\begin{align}
    \theta_{\student}^{(k + 1)}
    &= \theta_{\student}^{(k)} - \eta^{(k)}\nabla_{\theta_{\student}}\hat{L}_{\dino-\student\teacher}^{(k)}(\theta_{\student}^{(k)}, \theta_{\teacher}^{(k)}, \vW^{(k)}, \vmu^{(k)}) \\
    \theta_{\teacher}^{(k + 1)}
    &= \lambda^{(k)}\theta_{\teacher}^{(k)} + (1 - \lambda^{(k)})\theta_{\student}^{(k + 1)} \\
    \vW^{(k + 1)}
    &= \vW^{(k)} - \eta^{(k)}\nabla_{\vW}\hat{L}_{\dino-\student\teacher}^{(k)}(\theta_{\student}^{(k)}, \theta_{\teacher}^{(k)}, \vW^{(k)}, \vmu^{(k)}) \\
    \vmu^{(k + 1)}
    &= \lambda^{(k)}\vmu^{(k)} + (1 - \lambda^{(k)})\cdot\frac{1}{BM_{\glo}}\sum_{b = 1}^{B}\sum_{i = 1}^{M_{\glo}}\vW^{(k)}\vz_{b, g}^{t, i}(\theta_{\teacher}),
\end{align}
i.e., \(\vmu^{(k + 1)}\) is an exponential moving average of the average projected feature. Analogous update rules can be constructed for Adam and other iterative optimizers, all having the general form
\begin{align}
    \theta_{\student}^{(k + 1)}
    &= \textsc{OptimizationUpdate}^{(k)}(\theta_{\student}^{(k)}; \nabla_{\theta_{\student}}\hat{L}_{\dino-\student\teacher}^{(k)}(\theta_{\student}^{(k)}, \theta_{\teacher}^{(k)}, \vW^{(k)}, \vmu^{(k)})) \\
    \theta_{\teacher}^{(k + 1)}
    &= \lambda^{(k)}\theta_{\teacher}^{(k)} + (1 - \lambda^{(k)})\theta_{\student}^{(k + 1)} \\
    \vW^{(k + 1)}
    &= \textsc{OptimizationUpdate}^{(k)}(\vW^{(k)}; \nabla_{\vW}\hat{L}_{\dino-\student\teacher}^{(k)}(\theta_{\student}^{(k)}, \theta_{\teacher}^{(k)}, \vW^{(k)}, \vmu^{(k)})) \\
    \vmu^{(k + 1)}
    &= \lambda^{(k)}\vmu^{(k)} + (1 - \lambda^{(k)})\cdot\frac{1}{BM_{\glo}}\sum_{b = 1}^{B}\sum_{i = 1}^{M_{\glo}}\vW^{(k)}\vz_{b, g}^{t, i}(\theta_{\teacher}),
\end{align}
\textit{Importantly,} the gradients here only propagate through the \textit{first} argument of \(d_{\CE}\) in all invocations in \(L\) or \(\hat{L}\) (i.e., the outputs of the \textit{student} model). No gradients propagate through the second argument, as if the second argument is a fixed constant during differentiation. In other words, the teacher can be considered ``frozen'' or ``detached from the computational graph'' during the optimization step. After training, we discard the student weights and use the teacher weights for our trained network \(f\).

The simplified DINO objective is very similar in spirit but much simpler in execution, i.e.,
\begin{equation}\label{eq:simdino_loss_teacherstudent}
    L_{\simdino-\student\teacher}(\theta_{\student}, \theta_{\teacher}) :=  \Ex\rs{d_{\ell^{2}}(\vz_{c}(\theta_{\student}), \vz_{g}(\theta_{\teacher}))} + \frac{\gamma}{2}\logdet\rp{\vI + \frac{d}{\eps^{2}}\Cov(\vz_{g}(\theta_{\student}))},
\end{equation}
with, again, an analogous stochastic loss \(\hat{L}_{\simdino-\student\teacher}^{(k)}\) on iteration \(k\). We use the same optimization methodology to train the simplified DINO, i.e.,
\begin{align}
    \theta_{\student}^{(k + 1)}
    &= \textsc{OptimizationUpdate}^{(k)}(\theta_{\student}^{(k)}; \nabla_{\theta_{\student}}\hat{L}_{\simdino-\student\teacher}^{(k)}(\theta_{\student}^{(k)}, \theta_{\teacher}^{(k)})) \\
    \theta_{\teacher}^{(k + 1)}
    &= \lambda^{(k)}\theta_{\teacher}^{(k)} + (1 - \lambda^{(k)})\theta_{\student}^{(k + 1)}.
\end{align}


\subsection{Evaluation Methodology}\label{sub:contrastive_learning_evals}
There are several ways to evaluate a trained transformer model. We highlight two in this section.

\paragraph{Linear Probing}

The first, and most architecture-agnostic, way to evaluate an encoder model \(f_{\theta} \colon \R^{D \times N} \to \R^{d}\) is to employ \textit{linear probing}. Linear probing is, in a sentence, running logistic regression on the features computed by the encoder. This tells us how much semantic information exists in the representations, as well as how easily extractable this information is. (That is: to what extent do the features of images with different semantics live on different subspaces of the feature space?)

More formally, let us suppose that we want to evaluate the quality and faithfulness of the features of the encoder on a labeled dataset \(\{(\vX_{1}, \vy_{1}), \dots, (\vX_{B}, \vy_{B})\}\), where there are \(C\) classes and each \(\vy_{b} \in \{0, 1\}^{C}\) is a ``one-hot encoding'' (namely, zeros in all positions except a \(1\) in the \(c\th\) position if \(\vX_{b}\) is in the \(c\th\) class). One way to do this is to solve the logistic regression problem 
\begin{equation}\label{eq:linear_probing}
    \min_{\vW \in \R^{C \times d}}\frac{1}{B}\sum_{b = 1}^{B}\CE(\vy_{b}, \vW f_{\theta}(\vX_{b})).
\end{equation}
This problem is a convex optimization problem in \(\vW\), and thus can be solved efficiently via (stochastic) gradient descent or a litany of other algorithms. This linear probe, together with the encoder, may be used as a classifier, and we can evaluate the classification accuracy. The usual practice is to train the model first on a large dataset, then train the linear probe on a dataset, and evaluate it on a third (``holdout'') dataset which is drawn from the same distribution as the second one. This evaluation procedure is the most statistically sound.

\paragraph{Fidelity of the attention maps.}

Another way to check the performance of the representations is to examine the fidelity of the attention maps \(\vA^{L, k} \in \R^{n \times n}\) as defined in \Cref{eq:attention_map}, at the last layer \(L\), and given by the following pipeline:
\begin{align}
    \vX \mapsto \cdots \mapsto \vZ^{L - 1} = [\underbrace{\vz_{1}^{L - 1}}_{\text{class token}}, \underbrace{\vz_{2}^{L - 1} \dots, \vz_{n}^{L - 1}}_{\text{patch tokens}}] \mapsto \vA^{k, L} = \mat{\vA_{1, 1}^{k, L} & \vA_{1, 2:}^{k, L} \\ \vA_{2:, 1}^{k, L} & \vA_{2:, 2:}^{k, L}}.
\end{align}
In particular, we examine what the attention maps for a given input reveal about the salient objects in the input image, i.e., which parts of the image provide the most globally-relevant information to the class token. One particular way to do this is to examine the component of the attention map where the class token is extracted as the query and removed from the value matrix, i.e., \(\vA_{2:, 1}^{k, L} \in \R^{1 \times (n - 1)} = \R^{1 \times N}\) or its transpose \(\va^{k, L} \in \R^{N}\). Namely,
\begin{equation}
    \va^{k}(\vZ) := \softmax\rp{\frac{([\vU_{\key}^{k}]^{\top}\mat{\vz_{2}, \dots, \vz_{n}})^{\top}([\vU_{\query}^{k}]^{\top}\vz_{1})}{\sqrt{d}}}
\end{equation} 
Notice that this vector \(\va^{k, L}\), which we label as the ``\textit{saliency vector} at the \(k\th\) attention head at layer \(L\),'' has a value for every patch, \(1, \dots, N\), and we use this value to describe how relevant each patch is towards the global information. In particular for visualization's sake we create a new image where each patch is replaced by its corresponding value in the saliency vector, showcasing the contribution of each patch; we call this image the ``\textit{saliency map} at the \(k\th\) attention head at layer \(L\)''. \Cref{fig:attention_maps_saliency_dino} show visualizations of saliency maps in DINO and our simplified DINO; note that selected saliency maps highlight the relevant parts of the input image.

\section{Image Classification}\label{sec:image_classification}

In the previous section, we simplified an overly complex learning objective using our intuition of representation learning through the lens of compression. However, many of the most popular learning procedures are incredibly simple. In these cases, it is difficult to further simplify the objective. Thus, in this and future sections, we will focus on principled ways to modify the \textit{deep network architectures} for a variety of tasks.

Let us first start with arguably the most classical task in machine learning: \textit{image classification}, which is often used as a standard task to evaluate pattern recognition algorithms or deep network architectures. 

The dataset stays largely the same as \Cref{sub:contrastive_learning_data}, i.e., both the training and test data are labeled images.

\subsection{Task and Objective} \label{sub:image_classification_objective}

Unlike before, our task is not just to learn a good representation of the data, but also simultaneously build a classifier. Formally, we have labeled data pairs \((\vX, \vy)\); a classifier is a tuple \((f_{\theta}, \vW)\) where \(f_{\theta} \colon \R^{D \times N} \to \R^{d}\) is a transformer-based encoder and \(\vW \in \R^{C \times d}\) is a classification head. The map \(\hat{\vy}_{\theta, \vW} \colon \R^{D \times N} \to \Delta_{C}\) given by
\begin{equation}
    \hat{\vy}_{\theta, \vW}(\vX) = \softmax[\vW f_{\theta}(\vX)]
\end{equation}
maps data \(\vX \in \R^{D \times N}\) to predicted (smoothed) labels \(\hat{\vy}_{\theta, \vW}(\vX) \in \Delta_{C}\). The learning problem attempts to minimize the distance between \(\hat{\vy}\) and \(\vy\) as much as possible. Namely, suppose that we have some fixed data points \(\)
\begin{equation}\label{eq:classification_ce_loss}
    \min_{\theta, \vW}L(\theta, \vW) := \Ex[\CE(\vy, \hat{\vy}_{\theta, \vW}(\vX))].
\end{equation}
For evaluation, we use all evaluation methods for the feature map \(f_{\theta}\) that were posited in \Cref{sub:contrastive_learning_evals}.


\subsection{The CRATE Architecture}\label{sub:image_classification_crate}

The architecture that we use is the CRATE architecture, described in some level of detail in \Cref{ch:representation}. The overall setup is similar to that of the regular transformer in \Cref{sub:contrastive_learning_architecture}, with a few changes. While the pre-processing and post-processing steps are the same, each layer takes the form
\begin{align}
    \vZ^{\ell + 1/2}
    &= \vZ^{\ell} + \MSSA^{\ell}(\LN_{1}^{\ell}(\vZ^{\ell})), \\ 
    \vZ^{\ell + 1}
    &= \ISTA^{\ell}(\LN_{2}^{\ell}(\vZ^{\ell + 1/2})),
\end{align}
where the \(\MSSA\) and \(\ISTA\) blocks are as described in \Cref{ch:representation}, namely:
\begin{itemize}
    \item The \(\MSSA\) operator is multi-head-subspace-self-attention, defined as follows:
    \begin{align}
        \MSSA(\vZ) 
        &:= \vU_{\out}\mat{([\vU^{1}]^{\top}\vZ)\vA^{1}(\vZ) \\ \vdots \\ ([\vU^{K}]^{\top}\vZ)\vA^{K}(\vZ)} \\ 
        \text{where} \qquad \vA^{k}(\vZ) 
        &:= \softmax\rp{\frac{([\vU^{k}]^{\top}\vZ)^{\top}([\vU^{k}]^{\top}\vZ)}{\sqrt{d}}}
    \end{align}
    where \(\vU^{k} \in \R^{d \times p}\) and \(\vU_{\out} \in \R^{d \times Kp}\) are the trainable parameters this time.
    \item The \(\ISTA\) operator is iterative-shrinkage-thresholding-algorithm operator, defined as follows:
    \begin{equation}
        \ISTA(\vZ) := \ReLU(\vZ - \eta \vD^{\top}(\vD\vZ - \vZ) + \eta\lambda \vone_{d}\vone_{n}^{\top}),
    \end{equation}
    so named because the map \(\vX \mapsto \ReLU(\vX - \eta \vD^{\top}(\vD\vX - \vZ))\) is one step of the well-established ISTA algorithm to find an element-wise non-negative sparse representation for \(\vZ\).
\end{itemize}

We call this architecture CRATE. CRATE models, on top of being interpretable, are generally also highly performant as well as parameter-efficient. \section{Scaling White-Box Transformers}\label{sec:scalable}

In this section, we will discuss three ways in which various parts of CRATE-type models can be scaled up or made more efficient while still remaining white-box. These developments mix both conceptual and empirical insights, and can be viewed as case studies about how to use white-box understanding to improve deep learning models in practice. The task we use to evaluate the methods will be image classification, the data will be ImageNet, the optimization procedure will be the same backpropagation, and the only thing that changes is the architecture.

\subsection{Increasing Network Width: CRATE-\(\alpha\)}\label{sub:crate_alpha_experiments}

One design decision enforced by the CRATE framework is that the \textit{width} of the nonlinearity in the network. In a regular transformer, the width is usually set to \(4\), \(8\), or \(\frac{11}{3}\) times the feature dimension. However, CRATE enforces that the width is exactly equal to the feature dimension, i.e., the dictionaries \(\vD\) are square, which could lead to reduced performance. The fundamental reason that the CRATE framework constrains us to this choice is as follows:
\begin{itemize}
    \item The ISTA block takes a \textit{single} step of optimization for dictionary learning.
    \item Usually one step of any iterative optimization algorithm cannot effectively optimize the objective. So then why does this work?
    \item Optimization algorithms usually converge very quickly if and only if they have good initializations, or \textit{warm starts}. The ISTA block has a warm start --- it treats the input features as an initialization to the resulting sparse codes.
    \item This enforces that the input features and sparse codes are have the same dimension. Namely, ISTA learns a complete sparsifying dictionary (cf \Cref{ch:classic}).
\end{itemize}
Thus if we want to use a wide dictionary, we need ISTA to perform overcomplete dictionary learning. This means we cannot have the same warm start (as our sparse codes have larger dimension than our features), and need more iterations to converge to a sparse code. Hence the step from features \(\vZ^{\ell + 1/2}\) to sparse codes \(\vZ^{\ell + 1}\) would no longer be 
\begin{equation}
    \vZ^{\ell + 1} = \ISTA^{\ell}(\vZ^{\ell + 1/2} \mid \vZ^{\ell + 1/2})
\end{equation}
where the \(\ISTA^{\ell}\) function is defined as (by an abuse of notation from earlier sections)
\begin{equation}
    \ISTA^{\ell}(\vZ \mid \vX) := \ReLU(\vZ - \eta (\vD^{\ell})^{\top}(\vD^{\ell}\vZ - \vX) + \eta \lambda \vone_{m}\vone_{n}^{\top})
\end{equation}
but rather the following iteration:
\begin{equation}
    \vZ^{\ell + 1} = \vA_{T}^{\ell}; \qquad \vA_{t + 1}^{\ell} = \ISTA^{\ell}(\vA_{t}^{\ell} \mid \vZ^{\ell + 1/2}) \quad \forall 0 \leq t < T; \qquad \vA_{0}^{\ell} = \vzero,
\end{equation}
i.e., running proximal gradient on the LASSO objective for \(T \geq 1\) steps in the forward pass at each layer, initialized at \(\vzero\). In this circumstance, the dictionary can be as wide as needed, i.e., \(\vD^{\ell} \in \R^{m \times n}\) where \(m \geq d\) (usually one takes \(m = 4d\) in practice). 

However, this presents an empirical problem. Using the above configuration, if \(\vZ^{\ell + 1/2} \in \R^{d \times n}\) then \(\vZ^{\ell + 1} \in \R^{m \times n}\), which can have arbitrarily large feature dimension. In practice, we want the feature dimension at each layer to be the same. So this sets up a practical trichotomy for designing the network, namely, we \textit{cannot} have \textit{all} of the following desiderata:
\begin{enumerate}
    \item The feature dimension at each layer is the same.
    \item The dictionary is wide, i.e., overcomplete.
    \item The output of the nonlinearity is the sparse codes of the input w.r.t.~the dictionary.
\end{enumerate}
In practice, giving (1) is less tractable for efficiency reasons. Giving up (2) leads to the usual CRATE framework. Giving up (3) leads to a wide version of CRATE, i.e., CRATE-\(\alpha\), which has the following nonlinearity to get from \(\vZ^{\ell + 1/2}\) to \(\vZ^{\ell + 1}\):
\begin{equation}
    \vZ^{\ell + 1} = \vD^{\ell}\vA_{T}^{\ell}; \qquad \vA_{t + 1}^{\ell} = \ISTA^{\ell}(\vA_{t}^{\ell} \mid \vZ^{\ell + 1/2}); \qquad \vA_{0}^{\ell} = \vzero,
\end{equation}
i.e., takes the sparse codes obtained via proximal gradient descent and multiplies by the dictionary, to get the denoised version of the input. Thus CRATE-\(\alpha\)'s nonlinearity computes a denoised version of the input which is amenable to sparse coding, not the actual sparse codes themselves.

In practice this modification performs very well at both supervised tasks like image classification (see Table \DP{TODO}) and unsupervised tasks like segmentation (see Table \DP{TODO} and Figure \DP{TODO}). It generally improves the computational capacity significantly compared to CRATE, and is a promising avenue to scaling up the performance to match black-box models such as transformers.  \DP{TODO: Druv}

\subsection{Linear Time Complexity Transformer ToST}\label{sub:tost_experiments}

In practice, deep learning models suffer bottlenecks to space and time complexity, representing problem sizes which they cannot scale beyond given fixed resources. One such bottleneck, particularly meaningful when dealing with data where each sample is itself high-dimensional and rich (such as long streams of text or videos), is the \textit{time complexity} of processing long sequences of data. In order to alleviate the time-complexity of processing data using transformers, we can apply white-box thinking. In particular, we can use the ToST architecture (see \Cref{sub:tost}) for long-context tasks. In particular, denoting the ToST attention operator as \(\TSSA\) (for ``Token Statistics Self-Attention''), we use the following layer as a drop-in replacement for a layer in CRATE:
\begin{align}
    \vZ^{\ell + 1/2}
    &= \vZ^{\ell} + \TSSA^{\ell}(\LN_{1}^{\ell}(\vZ^{\ell})) \\ 
    \vZ^{\ell + 1}
    &= \vZ^{\ell + 1/2} + \MLP^{\ell}(\LN_{2}^{\ell}(\vZ^{\ell + 1/2}))
\end{align}
Notice that this is exactly the same as a vision transformer architecture as discussed in \Cref{sub:contrastive_learning_architecture}, except that \(\TSSA\) replaces the conventional multi-head self-attention block \(\MHSA\). Regardless, the computational complexity of the forward pass of this layer is linear in all problem variables --- sequence length, feature dimension, number of heads, and head dimension.

Moreover, the proposed architecture, named ToST (for ``Token Statistics Transformer'') is highly performant at vision tasks (cf Table \DP{TODO} and Figure \DP{TODO}). This is especially true for long-sequence-length tasks (cf Table \DP{TODO}), where it is both more performant and much more efficient than conventional transformers.

\subsection{Attention Only Transformer AoT} \label{sub:aot_experiments}

Another bottleneck to remove from deep learning models, specifically transformer-like architectures, is the memory bottleneck which comes from massive matrix multiplications in MLPs, where the internal dimension is far greater than the feature dimension \(d\). It thus is an interesting and important question to ask: do we \textit{really} need the MLP inside a transformer, and how good can the performance get without it? To explore this question, we use the AoT architecture (see \Cref{sub:aot}). Namely, each layer is simply of the form 
\begin{equation}
    \vZ^{\ell + 1} = \vZ^{\ell} + \MSSA^{\ell}(\LN^{\ell}(\vZ^{\ell})).
\end{equation}

\section{Masked  Autoencoding for Text and Image}\label{sec:image_completion}

The second application we discuss is \textit{nonlinear image completion}, which is a direct generalization of the low-rank matrix completion problem discussed in Chapter \ref{ch:classic}. Recall that the setup is as follows:
\begin{itemize}
    \item A pre-processing layer, which linearly projects the input data and adds a lelarnable \textit{positional embedding} to distinguish different token positions.
    \item \(L\) different CRATE encoding layers, whose design is specified in Chapter \ref{ch:representation}. 
    \item \(L\) different CRATE decoding layers, whose design is specified in Chapter \ref{ch:consistent}.
    \item A post-processing layer, which projects the decoded features into image space.
\end{itemize}
For both encoder and decoder layers, as in the previous setting, we replace the MSSA block's output matrix with a trainable output matrix.

Mathematically we have 
\begin{equation}
    \hat{\vX} = (g \circ f)(\vX) = (f^{\mathrm{post}} \circ \tilde{f}^{L - 1} \circ \cdots \circ \tilde{f}^{0} \circ f^{L} \circ \cdots \circ f^{1} \circ f^{\mathrm{enc}})(\vX) 
\end{equation}
where \(f^{\ell}\) are encoder layers and \(\tilde{f}^{\ell}\) are decoder layers, and 
\begin{equation}
    f^{\mathrm{pre}}(\vX) = \vW^{\mathrm{pre}}\vX + \vE^{\mathrm{pos}}, \qquad f^{\mathrm{post}}(\vZ) = \vW^{\mathrm{post}}\vX
\end{equation}
Here, the parameters may be learned by a variety of methods which encourage certain representations \(\vZ\) as well as certain notions of consistency between \(\vX\) and \(\wh{\vX}\). Again, we consider learning methods which promote learning the semantically relevant parts of the distribution. Inspired by the low-rank matrix completion task (for which the connection to learning high-dimensional distributions, such as images, is provided in Chapter \ref{ch:consistent}), we train using the \textit{masked autoencoding} pretext task. Namely, for a random index set \(\Omega \subseteq [N]\) of tokens to be kept and a projection onto this random index set \(P_{\Omega}\) defined as 
\begin{equation}
    P_{\Omega}(\vX) = \casework{\vX_{ij}, & j \in \Omega, \\ 0, & j \notin \Omega,}
\end{equation}
we train on the objective
\begin{equation}
    L_{\mathrm{MAE}}(f, g) \doteq \Ex_{\vX, \Omega}\norm{(g \circ f)(P_{\Omega}(\vX)) - \vX}_{2}^{2}.
\end{equation}

Unlike in the previous setting, this objective function encourages the network to learn representations of the input data that enable masked completion. Namely, each token representation should contain both local information about its patch, and global information about the statistics of the whole image. Thus, again, we expect that the representations should contain both local and global semantically relevant information, and the representations of different patches with similar local and global information should be related. As in the previous section, we can directly visualize these relationships. Figure \DP{TODO} demonstrates that the learned features in CRATE-MAE still correspond to semantically relevant components of the data in straightforward ways, \textit{even when no labels at all are provided during training}! To evaluate the performance of deep networks trained using self-supervised learning methods such as masked autoencoding, a standard technique is to use ``linear probing'': for a given dataset \((\vX, \vy)\) and a pre-trained encoder \(f\), solve the logistic regression problem 
\begin{equation}
    L_{\mathrm{LP}}(\vW) \doteq L_{\CE}(\softmax \circ \vW \circ [f(\vX)(N^{-1}\vone)]).
\end{equation}
That is, we average the features \(\vZ = f(\vX)\) as \(\vZ(N^{-1}\vone) = \frac{1}{N}\sum_{i = 1}^{N}\vz_{i}\) to get a ``summary representation'', then use a linear classifier to classify the input data using this summary. We train the classifier via the cross-entropy loss. It is also possible to modify the training procedure to use a class token, as in the previous section. Here, for each ``backbone'' model \(f\) (either \(f_{s}\) or \(f_{t}\)), we can write (as in other experimental settings) \(f = f^{L} \circ \cdots \circ f^{1} \circ f^{\pre}\), where the pre-processing map $f^{\pre}: \bR^{D \times N} \to \bR^{d \times n}$ is defined as
% \begin{equation}

% \end{equation}
% where $n = N + 1$ and $\vz_{\mathrm{cls}}^{1} \in \bR^{d}$,  $\vW^{\pre} \in \bR^{d \times D}$ and $\vE_{\mathrm{pos}} \in \bR^{d \times n}$ are trainable parameters, and each layer \(f^{\ell} \colon \bR^{d \times n} \to \bR^{d \times n}\) is a transformer layer, such as the CRATE layer or ViT layer. Each projection map \(f^{\mathrm{proj}} \colon \bR^{d \times n} \to \bR^{d}\) (either \(f_{s}^{\mathrm{proj}}\) or \(f_{t}^{\mathrm{proj}}\)) is defined, as in \cite{caron2021emerging}, as 
% \begin{equation}\label{eq:dino_head}
%     f^{\mathrm{proj}}(\mat{\vz_{1}, \dots, \vz_{n}}) = \vW_{3}^{\mathrm{proj}}\operatorname{ReLU}(\vW_{2}^{\mathrm{proj}}\operatorname{ReLU}(\vW_{1}^{\mathrm{proj}}\vz_{1} + \vb_{1}^{\mathrm{proj}}) + \vb_{2}^{\mathrm{proj}}) + \vb_{3}^{\mathrm{proj}},
% \end{equation}

% \paragraph{Pre-training methodology.} 

% We parameterize \((f_{s}, f_{s}^{\mathrm{proj}})\) by a parameter set \(\vtheta_{s}\), and similarly parameterize \((f_{t}, f_{t}^{\mathrm{proj}})\) by a parameter set \(\vtheta_{t}\). % \begin{equation}\label{eq:dino-objective}

The views are distorted crops of the original image. A global view is a high-resolution (e.g. $224\times 224$) crop that covers a large (e.g. $>50\%$) area of the input image while a local view is of lower resolution (e.g. $96\times 96$) and covers a smaller (e.g. $<50\%$) area of the original image.} %R\DP{@YY @ZYW: what are these? can you give details/examples} \ZW{Explanation added in the footnote}
% , and the probability $P(\cdot; \cdot, \cdot)$ is defined as

% The training is done in the following (slightly unintuitive) way using exponential moving averages:
% \begin{align}
